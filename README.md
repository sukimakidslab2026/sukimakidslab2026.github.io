# すきまキッズラボ サイト（スタンプラリー）

GitHub Pages + Supabaseで公開するための構成です。Supabaseを正本のデータベースとし、
Googleスプレッドシートは閲覧・集計用の同期先にしています。

**公開URL：`https://sukimakidslab2026.github.io/`**

## 1. サイトの構成

| ページ | URL | 内容 |
|---|---|---|
| トップページ | `https://sukimakidslab2026.github.io/` | 「すきまキッズラボ」とは？（プロジェクトの紹介。内容は準備中） |
| スタンプラリー | `…/rally/` | 掲示板のQRコードを読み取ると、スタンプがたまる。QRコードは `…/rally/?stamp=（掲示板のコード）` |
| アンケート | `…/survey/` | スタンプが条件（3個）に達した人だけが回答できる。景品の希望もここ |
| 管理画面 | `…/admin/` | 運営者用（ログインが必要） |

- **すべての公開ページの左上にロゴ**（押すとトップページへ）、**右上にメニュー（≡）** があります。メニューには、「スタンプラリー」「「すきまキッズラボ」とは？」と、その下にInstagramのアイコンがあります（管理画面には、ありません）。
- 参加者の流れ：掲示板のQRコードを読み取る → 3個たまる → アンケートに回答（景品を希望する場合は、発送先も入力）。**掲示板は十数か所あり、どの3か所でも構いません。**

| フォルダ・ファイル | 内容 |
|---|---|
| `index.html`, `style.css` | トップページ |
| `rally/` | スタンプラリー（`index.html`・`app.js`・`style.css`） |
| `survey/` | アンケート・プライバシー規約 |
| `admin/` | 管理画面 |
| `assets/` | ロゴ・アイコンの画像 |
| `js/` | `config.js`（Supabaseの接続設定）、`rally-data.js`（場所・景品の補足の設定）、`site-nav.js`（メニューの開閉） |
| `brand.css` | 色・フォント・共通ヘッダー（ロゴ・メニュー）のスタイル |
| `sql/schema.sql` | データベースの定義（Supabaseで実行） |
| `gas/sheets-sync.gs` | スプレッドシートへの自動同期（Google Apps Script） |
| `scripts/` | `make_boards.py`（掲示板のQRコードを作る）、`stamp_assets.py`・`check_site.py`（公開前のチェック） |
| `qr/` | QRコードの画像。**`qr/boards/`（掲示板のQRコード）は、GitHubに公開されません**（4章） |

## 2. Supabase設定

1. Supabaseで新規プロジェクトを作成
2. SQL Editorで `sql/schema.sql` を実行（何度実行しても同じ結果になります。既存のデータは消えません）
3. 掲示板のQRコードを作り、SQL Editorで `qr/boards/boards_seed.sql` を実行する（**4章**。これをしないと、QRコードを読み取っても、スタンプになりません）
4. Project Settings > API から URL と anon/publishable key を確認
5. `js/config.js` の2項目を変更
6. GitHub Pagesへ公開

Supabaseを設定しなくても（`js/config.js` が初期値のままでも）、`rally/?stamp=abcdef12` のようなURLで動作を試せます。
この「デモモード」では、形式（英小文字・数字の6〜32文字）が合うコードなら何でもスタンプになり、端末のlocalStorageだけに保存します。

### 管理者の登録

管理画面（`admin/`）は、Supabase Authでログインし、かつ `admin_users` に登録されたユーザーだけが閲覧できます。

1. Authentication > Users > Add user で管理者のメールアドレスとパスワードを作成
2. SQL Editorで次を実行（メールアドレスを変更）

   ```sql
   insert into public.admin_users (user_id)
   select id from auth.users where email = 'admin@example.com'
   on conflict do nothing;
   ```

3. Authentication > Sign In / Providers で「Allow new users to sign up」をオフにする（第三者のアカウント作成を防ぐため）

Supabaseのダッシュボード（Table Editor・SQL Editor）からは、この設定に関係なく全データを閲覧できます。

## 3. 景品の条件（スタンプの個数）

- **掲示板のQRコードを3個以上読み取ると、景品を希望できます**（アンケートに進めます）。同じ掲示板を何度読み取っても、スタンプは1個です。
- 条件を達成したあとも、ほかの掲示板を読み取れます（スタンプの枠が増え、記録も残ります）。
- 画面上部のバナーに、取得数（◯/3）と、あと何個かを表示します。文言は、取得状況で切り替わります：0個「スタンプを集めて、景品の希望に進もう！」／途中「あと◯個で、景品を希望できるよ！」／残り1個「あと1個！景品の希望まで、あと少し！」／3個「コンプリート！景品を希望できる条件を達成したよ！」
- 「景品がもらえる」とは書かず、「景品を希望できる」と表示しています（景品の在庫や受け取り条件は、このサイトでは定義していないため）。
  在庫・条件を運営側で確認したうえで、`js/rally-data.js` の `RALLY_PRIZE.notice` に補足（例：「景品がなくなり次第、終了します」）を入力すると、バナーに表示されます。
- **個数を変える場合は、2か所を同じ数にします：** `rally/app.js` の `PRIZE_REQUIRED` と、`sql/schema.sql` の `rally_required_stamps()`（`select 3;`）。
  さらに、`rally/index.html` の初期表示（`requiredCount`・`total`・`aria-valuemax` の `3`）も変えます。`python3 scripts/check_site.py` が、これらが一致しているかを確認します。
  変えたあとは、SQL（`sql/schema.sql` 全体）をSupabaseで実行し直してください。
- 「視差効果を減らす」を選んでいる端末では、アニメーションは止まり、最終の状態だけが表示されます。

## 4. 掲示板のQRコード

### しくみ

- 掲示板ごとに、**別々のQRコード**を掲示します（十数か所。初期設定は15か所）。QRコードには、掲示板ごとの「コード」（8文字の英数字）が入っています：
  `https://sukimakidslab2026.github.io/rally/?stamp=（コード）`
- **コードは、推測されにくいランダムな文字列です。** 連番（01, 02…）にすると、URLを書き換えるだけで、掲示板に行かなくてもスタンプを取れてしまうためです。
- 有効なコードは、Supabaseの `stamp_boards` テーブルに登録されたものだけです。登録されていないコード（古いQR・まちがいなど）を読み取ると、画面に「このQRコードは登録されていません」と表示され、何も記録されません。
- 掲示板の番号（No.01〜）は、管理画面・スプレッドシートで「どの掲示板がよく読み取られているか」を見るための番号です（参加者の画面には、出しません）。

### QRコードを作る（最初に1回、掲示板の数が変わったとき）

1. ターミナルで、このフォルダを開く
2. 最初だけ：`pip3 install segno pillow`
3. `python3 scripts/make_boards.py`（15個。数を変える場合は `python3 scripts/make_boards.py --count 18`）
   - すでにあるコードは変わらず、増やした分だけ新しいコードが作られます。**減らすことはできません**（作成済みのコードは残ります）。
   - 日本語の題名には、サイトと同じ筑紫A丸ゴシック（Macに入っているもの）を使います。見つからないときは、`--font（フォントファイルの場所）` で指定します。
4. できるもの（すべて A3・縦・300dpi。印刷は、「拡大縮小なし（実際のサイズ）」で）：

   | ファイル | 内容 |
   |---|---|
   | `qr/boards/board_01.png` … | QRコードだけ（ご自身のデザインに組み込むとき用） |
   | `qr/boards/board_01_title.png` … | 上に「スタンプラリー」、QRコードの下に「No.01」の番号を入れたもの |
   | `qr/boards/boards.csv` | 掲示板の番号・コード・URLの一覧（**元データ。なくさないでください**） |
   | `qr/boards/boards_seed.sql` | Supabaseに掲示板のコードを登録するSQL |
   | `qr/qr_top.png`, `qr/qr_top_title.png` | トップページ（「すきまキッズラボ」とは？）を開くQRコード |
   | `qr/qr_rally.png`, `qr/qr_rally_title.png` | スタンプラリーのページを開くQRコード（スタンプはつきません） |

5. SupabaseのSQL Editorで、`qr/boards/boards_seed.sql` の全体を貼り付けて Run する。最後に表示される「登録済み」と「期待する数」が、同じ数なら、登録できています。
   （何度実行しても問題ありません。掲示板を増やしたときも、同じファイルをもう一度実行します）
6. **印刷する前に、必ず実機で確認する：** スマートフォンのカメラで読み取り、スタンプが取れること（テスト用の記録は、あとで管理画面の「テストデータの除外」で除外します）。

### 大切な決まり

- **`qr/boards/` は、GitHubに送られません**（`.gitignore` で除外しています）。コードを知っていれば、掲示板に行かなくてもスタンプを取れてしまうためです。
  このフォルダは、パソコンの中（できれば、非公開の別の場所にもバックアップ）に、保管してください。`boards.csv` をなくすと、同じコードを作り直せません（Supabaseの `stamp_boards` テーブルから、番号とコードを取り出すことはできます）。
- `python3 scripts/check_site.py` が、掲示板のコードが、公開されるファイルに混ざっていないかも確認します。
- `qr/` の直下にあるのは、トップページ・スタンプラリーのページを開くだけのQRコードです（隠す必要のないもの）。

### 掲示板を入れ替える・なくす

- 特定の掲示板のQRコードを使わなくなった場合は、SupabaseのSQL Editorで、そのコードを削除します：
  `delete from public.stamp_boards where board_no = 7;`（7番の例。すでに取得されたスタンプの記録は、そのまま残ります）
- 新しい掲示板を追加する場合は、`--count` を増やして、手順3〜6を行います。

## 5. 記録される内容（Supabase）

| テーブル | 内容 |
|---|---|
| `stamp_boards` | 有効なQRコード（掲示板）の一覧。コードと番号。管理者以外は読み取れない |
| `scan_events` | QRの全読み取り履歴（再スキャンも含む）。`is_first_claim` で初回取得（true）か再スキャン（false）かを区別。`user_agent` はブラウザ情報で、通信失敗後の再送は末尾に `[resend]` が付く。**登録されていないコードは、記録しない** |
| `stamp_claims` | 参加者ごとの初回スタンプ取得（取得順 `sequence` と初回取得時刻）。取得順に上限はない |
| `survey_responses` | アンケート回答（満足度・自由記述・ワークショップ参加有無・景品希望）。**個人情報は含まない** |
| `prize_shipping` | 景品の発送先（氏名・郵便番号・住所・電話番号・同意した規約の版）。景品を希望した人だけ。管理者以外は読み取れない |
| `excluded_participants` | 集計・CSV・スプレッドシートから外す参加者（テストなど）。データは削除されない |
| `admin_users` | 管理画面を使えるユーザー |

3個以上の `stamp_claims` が揃うと、アンケート画面へ進めます（判定はSupabase側の `submit_survey` 関数でも行います）。
アンケートでは、「景品を希望する」にチェックした人だけ、プライバシー規約に同意したうえで発送先を入力します。

### Supabaseのダッシュボードで読みやすく見る

Table Editor に、日本語の列名・日本時間で表示する閲覧用ビューがあります（ダッシュボード専用で、サイトからは読めません）。

| ビュー | 内容 |
|---|---|
| `ja_participants` | 参加者ごとの状況（獲得数、コンプリート日時、取得順＝掲示板の番号、端末など） |
| `ja_scan_log` | 読み取り履歴（新しい順。掲示板の番号、端末の種類、初回／再スキャン） |
| `ja_surveys` | アンケート回答（個人情報なし） |
| `ja_shipping` | 景品発送先（**個人情報あり**） |

## 6. 管理画面（`admin/`）

- 概要カード：参加者数・クリア人数（3個以上。クリア率）・総スキャン数（うち再スキャン）・アンケート回答（回答率）・景品希望・平均満足度・除外した参加者
- 集計：獲得数別の人数（どこで離脱しているか。景品の条件の行に印）、**掲示板別**（読み取り回数・人数・取得率。読み取りが0回の掲示板も載ります）、日別、ワークショップ参加別、満足度の分布
- 参加者の一覧（取得した掲示板の番号と時刻・端末）、QR読み込み履歴、アンケート。それぞれ絞り込みができます
  （履歴：参加者ID・掲示板・初回／再スキャン・期間。アンケート：景品希望・ワークショップ・期間。参加者：状態・ID）
- 景品発送先（個人情報）は、「景品発送先（個人情報）」を開いたときだけ表示されます
- 30秒ごとに自動更新（チェックを外すと止まります。「さらに読み込む」で増やした履歴の件数は保たれます）
- CSV：景品発送CSV（希望者のみ）・アンケートCSV（個人情報なし）。どちらも、押した時点の最新データから作り、除外した参加者は含みません
- **アンケート画面の確認（プレビュー）：** ダッシュボードの「アンケート画面を確認（プレビュー）」を押すと、コンプリートしていない端末でも、アンケート画面の全項目を確認できます。**送信しても、記録は保存されません。** 管理画面にログインしている管理者だけが使えます（参加者が `?preview=1` を付けても、使えません）。

### テストデータの除外

動作確認で読み取ったデータが集計に混ざらないよう、参加者を「除外」できます。除外してもデータは削除されず、いつでも元に戻せます。
除外した参加者は、概要・集計・CSV・スプレッドシートに含まれません（管理画面の表には「除外した参加者も表示」で表示できます）。

- 参加者ごと：参加者の表の「除外」ボタン
- まとめて：「テストデータの除外」で日時を指定すると、**その日時より前に最初の読み取りがあった参加者**がすべて除外されます。
  本番開始の直前の時刻を指定してください
- 元に戻す：参加者ごとの「除外を解除」、または「除外をすべて解除」

### テストデータを完全に消す（本番開始の直前に1回）

除外ではなく、記録そのものを消したい場合は、SupabaseのSQL Editorで、次を実行します。**元に戻せません。** 必要なら、先に管理画面でCSVを保存してください。

```sql
truncate table
  public.prize_shipping,
  public.survey_responses,
  public.stamp_claims,
  public.scan_events,
  public.excluded_participants
restart identity;
```

消えるのは、参加者の記録だけです。**掲示板の登録（`stamp_boards`）、管理者の登録、同期トークン、テーブルの構造は消えません。** 実行すると、次の5分ごとの同期で、スプレッドシートの中身も空になります。

**テストに使ったスマートフォンの記録も、消してください。** 参加者の記録（参加者ID・取得済みスタンプ）は、その端末のブラウザにも残っています。
このまま `rally/` を開き直すと、端末に残っているスタンプが、サーバーに再送されて、記録が復活します（通信に失敗したときの救済のしくみです）。
Safariなら「設定 > Safari > 履歴とWebサイトデータを消去」、Chromeなら「設定 > プライバシーとセキュリティ > 閲覧履歴データの削除」（サイトのデータ）で消すか、テストは、最初からプライベートブラウズ（シークレット）で行ってください。

## 7. プライバシー規約（公開前に必ず確認）

規約の本文は `survey/privacy.html` の1か所だけにあり、アンケート画面のモーダルにも同じ内容が表示されます。
`【要確認】` の箇所（運営者名・保管期間・第三者提供・委託・問い合わせ先・開示等の手続き・データの保存場所など）は、
運営者が正式な情報を記入してください。記入後は「下書き」の注意書きを削除し、`data-version` を更新します。
アンケート画面の「個人情報の取り扱い（要点）」（`survey/index.html`）にも `【要確認】` があります。
この規約は法令への適合を保証するものではないため、運営者側での確認を経てから公開してください。

## 8. Googleスプレッドシートへの自動同期

Supabaseを正本とし、スプレッドシートは閲覧・集計用の同期先にします（スプレッドシートからSupabaseへは書き戻しません）。
Google Apps Script（`gas/sheets-sync.gs`）が **5分ごとに「前回から変化があったか」だけを軽く確認** し、
変化がなければ何も書き換えません。変化があったときだけデータを取得して、各シートを書き直します。
GoogleのAPIキーやSupabaseのservice_role keyは使いません。必要なのは、読み取り専用の同期トークンだけです。

### 設定手順（初めて設定する場合）

1. SupabaseのSQL Editorで `select private.issue_sheets_token();` を実行し、表示された値を控える
   （再発行すると以前のトークンは無効になります。値はSupabaseにはハッシュとしてだけ保存されます）
2. 同期先のGoogleスプレッドシートを新規作成し、拡張機能 > Apps Script を開く
3. `gas/sheets-sync.gs` の内容をすべて貼り付けて保存
4. プロジェクトの設定 > スクリプト プロパティ に次を追加
   - `SUPABASE_URL`：`js/config.js` と同じURL
   - `SUPABASE_PUBLISHABLE_KEY`：`js/config.js` と同じ公開キー
   - `SHEETS_SYNC_TOKEN`：手順1の値
5. エディタで `setup` を選んで実行し、権限を許可する（タイムゾーンを日本時間に設定し、5分ごとの自動同期を設定し、最初の同期を行います）

### 作られるシート

| シート | 内容 |
|---|---|
| 概要 | 最終確認・最終更新の時刻、全体の数字、獲得数別の人数、ワークショップ参加別、満足度の分布、日別 |
| 参加者 | 1人1行（新しく動いた人が上）。状態、獲得数、コンプリート日時（3個目を取った時刻）、取得順（掲示板の番号）、読み取り回数、端末、アンケート回答、ワークショップ参加 |
| 掲示板別 | 掲示板（No.01〜）ごとの、総読み取り回数、ユニーク参加者数、再スキャン回数、取得者数、取得率 |
| アンケート | 回答日時、満足度、コメント、ワークショップ参加、景品希望（新しい順） |
| スキャン履歴 | 読み取り日時（新しい順）、参加者ID、掲示板、初回／再スキャン、端末の種類、再送 |
| 景品発送（個人情報） | 氏名・住所など。同期する設定にしたときだけ作られます（後述） |
| メモ・分析用 | 同期の対象外。自由にメモ・集計・グラフを作れます |

### 見方と注意

- **「概要」の「最終確認」** は、5分ごとにSupabaseを確認した時刻です。「変更なし」「更新しました」のどちらかも表示されます。
  「最終更新」は、データが変わってシートを書き換えた時刻です。止まっていないかは、この「最終確認」で分かります。
  「状態」が「正常」でなければ、原因がそこに表示されます（Googleからも失敗の通知メールが届きます）
- 同期されるシートは、**データが変わるたびに中身が書き直されます**。列の追加・並べ替え・色付けは消えます。
  自分用の集計やメモは「メモ・分析用」シートに作り、同期されるシートを参照してください
  （例：`=COUNTIF('参加者'!B:B,"コンプリート")`）
- 絞り込み・並べ替えをしたいときは、メニューの「データ → フィルタビュー」を使うと、書き直されても残ります
- 除外した参加者（テストなど）は、どのシートにも含まれません
- メニュー「スタンプラリー同期」から、「今すぐ同期」「全体を強制的に書き直す」「自動同期の開始・停止」ができます

### 「拡張機能 > Apps Script」で「ファイルを開くことができません」と出る場合

Googleの既知の不具合で、ブラウザで複数のGoogleアカウントに同時にログインしていると起こります（このプロジェクトとは無関係です）。次の順に試してください。

4. それでも開けない場合は、スプレッドシートに紐づけずに作る：

   4. `setup` を実行して権限を許可（メニュー「スタンプラリー同期」は表示されませんが、同期は動きます）

### 景品発送情報（個人情報）を同期する場合

初期設定では同期しません。同期する場合は、スクリプト プロパティに `SYNC_SHIPPING` = `true` を追加します。
個人情報を含むため、閲覧できる人を限定した**別のスプレッドシート**を用意し、
そのIDを `SHIPPING_SPREADSHEET_ID` に設定することをおすすめします（未設定ならこのスプレッドシートの「景品発送（個人情報）」シート）。

同期をやめても、作成済みのシートは自動では削除されません（「概要」に残っていることが表示されます）。不要になったら手動で削除してください。

## 9. 更新手順（すでに運用している場合）

「6か所すべてを集める」旧版から、「十数か所の掲示板のうち3個」の新版へ更新するときの手順です。
データベースの構造が変わります。**次の順に行ってください（SQL → 掲示板の登録 → プッシュ → Apps Script）。**
旧版の記録は消えません（旧版の6か所の名前は、「旧：川の入口」のように表示されます）。

1. （推奨）バックアップ：管理画面で、アンケートCSV・景品発送CSVを保存する
2. SupabaseのSQL Editorで、新しい `sql/schema.sql` の全体を貼り付けて実行する（エラーが出ないことを確認）
3. `python3 scripts/make_boards.py` で掲示板のQRコードを作り（4章）、SQL Editorで `qr/boards/boards_seed.sql` を実行する（「登録済み」と「期待する数」が同じ数になることを確認）
4. 旧版の動作確認のデータが不要なら、6章の「テストデータを完全に消す」を実行する
5. すぐに、変更したファイルをコミットしてGitHubにプッシュする（GitHub Pagesに反映されるまで1〜3分）：
   ```
   python3 scripts/stamp_assets.py
   python3 scripts/check_site.py       # 「0 件の問題」を確認
   git add -A
   git commit -m "掲示板3個のスタンプラリー・メニュー・トップページ"
   git push
   ```
   SQLの実行からプッシュまでの間は、旧版のスタンプラリー画面から、スタンプを取れません（新しい掲示板のコードしか、有効ではないため）。
6. スマートフォンで `https://sukimakidslab2026.github.io/rally/?stamp=（掲示板1のコード）` などを開き、スタンプが取れることを確認する（`qr/boards/boards.csv` のURL）。3個取ると、アンケートに進めることを確認する
7. 管理画面を開いてログインし、概要・掲示板別・参加者が表示されることを確認する（画面を再読み込みして最新版にする）
8. Googleスプレッドシート連携を使っている場合は、Apps Scriptを入れ替える：
   1. スプレッドシートの 拡張機能 > Apps Script を開く
   2. 既存のコードをすべて消して、新しい `gas/sheets-sync.gs` の内容を貼り付けて保存
   3. スクリプト プロパティは、そのまま使えます（変更不要）
   4. エディタで `setup` を選んで実行する（全シートが新しい形式で作り直されます）
   5. 「概要」シートで、「最終確認」が更新され、「状態」が「正常」になっていることを確認する
   6. 旧版の「スポット別」シートが残っていたら、手動で削除する（新しい形式は、「掲示板別」シートです）。「メモ・分析用」シートの例の数式が、旧版の列の位置を参照している場合は、直してください（アンケートの「ワークショップ参加」は、E列になりました）
9. 本番開始の直前に、動作確認のデータを除外または削除する（6章）
10. QRコードを印刷して、掲示板に掲示する（4章）

## 12. 掲示板のある場所（Googleマップ）

スタンプラリー画面の「掲示板のある場所」に、場所の名前・説明と、Googleマップへのリンク・地図を表示します。
**場所は、運営側が [js/rally-data.js](js/rally-data.js) に入力した内容だけを表示します（推測でピンは打ちません）。現在は、確認用の「仮の場所」として、座標（35°41'36.2"N 139°46'47.1"E ＝ 緯度 35.693389、経度 139.77975）が1か所だけ入っています。実際の場所が決まったら、書き換えてください。**

- 入力する項目（場所ごと。`RALLY_PLACES` の `{ … }` を、場所の数だけ並べます）：`name`（場所の名前）／`description`（場所の説明）／`address`（住所）／`lat`・`lng`（緯度・経度。入力すると住所より優先）／`mapQuery`（施設名など、Googleマップで探す言葉）
- 住所・座標・`mapQuery` のどれもない場所には、リンクを出さず「場所は準備中です。」と表示します。入力した座標が範囲外（緯度±90・経度±180を超える）の場合も、リンクを出しません。
- リンクは、Googleマップの公式の共有URL（APIキー不要・無料）です。住所や座標は、URLに入る前にエンコードされます。
  - 「Googleマップで場所を見る」：`https://www.google.com/maps/search/?api=1&query=…`
  - 「ここへの行き方」：`https://www.google.com/maps/dir/?api=1&destination=…&travelmode=walking`
  - スマートフォンでは、Googleマップのアプリが入っていればアプリで、なければブラウザで開きます。
- **地図の埋め込み**：場所ごとに、ピンを打ったGoogleマップ（地図・航空写真への切り替え・拡大縮小ができる埋め込み）を表示します。画面の近くまでスクロールしたときに読み込みます（`loading="lazy"`）。「地図を閉じる」で、たたむこともできます。APIキーは使わないため、課金は発生しません。
  - 最初は閉じておき、「地図を表示」を押したときだけ読み込みたい場合は、`RALLY_PLACES_PREVIEW_OPEN` を `false` にします。
  - この埋め込みの形式は、Googleの公式のAPI（Maps Embed API、キーが必要）ではないため、将来Googleが変更すると表示されなくなる可能性があります（その場合も、上のリンクは使えます）。埋め込みを使わない場合は、`RALLY_PLACES_PREVIEW` を `false` にします。
- **すべての掲示板をまとめた1枚の地図（掲示板が十数か所ある場合におすすめ）**：[Googleマイマップ](https://www.google.com/maps/d/)で、掲示板の場所にピンを立てた地図を作り、共有（リンクを知っている全員が閲覧可）にします。
  - `RALLY_MAP_VIEW_URL` に共有URL（`https://www.google.com/maps/d/viewer?mid=…`）を入力すると、「すべての掲示板の地図を開く」のボタンが出ます。
  - `RALLY_MAP_EMBED_URL` に埋め込み用URL（マイマップの「︙」→「自分のサイトに埋め込む」で表示される `iframe` の `src` の中の、`https://www.google.com/maps/d/embed?mid=…`）を入力すると、画面に地図が埋め込まれます。
  - Googleマップ・マイマップ以外のURLは、無視します。
- 場所を公開してよいか（設置場所の都合）は、運営側で確認してから入力してください。

## 13. 公開前のチェック（毎回）

GitHub Pagesは、ファイルをブラウザに10分間保存（キャッシュ）させます。公開した直後に、HTMLだけが新しく、CSSが古いままという組み合わせになると、
背景やフォントが古いままになったり、本来は隠れているはずの表示が見えたりすることがあります。これを防ぐため、HTMLが読み込むファイルのURLに、
ファイルの中身から作った版（`style.css?v=1a2b3c4d`）を付けています。**CSS・JavaScript・`js/rally-data.js` などを変更したら、コミットの前に、次を実行してください。**

```
python3 scripts/stamp_assets.py      # 版を更新する（変更があったHTMLの名前が表示されます）
python3 scripts/check_site.py        # サイト全体の整合性を検査する（「0 件の問題」になることを確認）
```

- `check_site.py` が調べること：HTMLの構造・IDの重複、JavaScriptが参照するIDの有無、読み込むファイルの存在、CSS変数の定義、ブランドカラー以外の色が使われていないか、フォントファイルが混ざっていないか、`hidden` の表示、版が最新か、JavaScriptの文法、秘密鍵が含まれていないか、`js/config.js` が変更されていないか、**共通ヘッダー（ロゴ・メニュー・Instagram）が4ページで同じか**、**景品の条件の個数がJavaScript・SQL・HTMLで同じか**、**掲示板のコードが公開されるファイルに含まれていないか**、旧仕様の記述が残っていないか。
- **自動で実行したい場合（最初に1回だけ）：** ターミナルで `git config core.hooksPath .githooks` を実行すると、コミットのたびに、版が自動で更新されます。
- 公開後、スマートフォンで古い表示が残る場合は、ブラウザの履歴・キャッシュを消すか、10分ほど待ってから開き直してください。

### 参加者のスマートフォンに保存されるもの

- スタンプの記録（参加者ID・取得済みスタンプ・取得時刻・未送信の分）は、**サイトのドメインごと**に、ブラウザに保存されます。ドメインが変わると、そのままでは引き継がれません（引き継ぐしくみは、ありません）。**QRコードを印刷・掲示したあとは、ドメインを変えないでください。**

### 独自ドメイン（`.com` など）を使う
GitHub PagesのSettings > Pages > **Custom domain** には、`.com` などの一般的なドメインを設定できます。**ドメインは、レジストラ（ドメインを販売する会社）で購入する必要があり、年額の費用がかかります**（金額はレジストラや種類によって異なります。購入前にご確認ください）。
**QRコードを印刷する前に、先に決めてください**（ドメインが変わると、QRコードを作り直す必要があり、参加者の保存データも引き継がれません）。

1. **ドメインを取得する：** 好みのレジストラでドメイン（例：`sukimakidslab.com`）を購入する。
2. **（推奨）ドメインの所有を確認する：** GitHubの、Organization「sukimakidslab2026」の Settings > Pages > 「Add a domain」から、ドメインを確認（verify）する。画面に表示された `TXT` レコードを、レジストラのDNS設定に追加します。他の人にドメインを乗っ取られることを防ぎます。
3. **DNSを設定する**（レジストラの画面）。次のどちらかです。
   - **`www.sukimakidslab.com` のようなサブドメインを使う場合（簡単）：** `CNAME` レコードを追加し、名前 `www`、値 `sukimakidslab2026.github.io`
   - **`sukimakidslab.com`（apex）を使う場合：** `A` レコードを4つ追加し、値は、`185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`（IPv6を使う場合は、`AAAA` に `2606:50c0:8000::153`、`2606:50c0:8001::153`、`2606:50c0:8002::153`、`2606:50c0:8003::153`）
   - 最新の値は、GitHubの公式ドキュメント「Managing a custom domain for your GitHub Pages site」で確認してください。
4. **GitHubで設定する：** リポジトリ `sukimakidslab2026.github.io` の Settings > Pages > Custom domain にドメインを入力して「Save」。リポジトリの直下に `CNAME` というファイルが自動で追加されるので、ターミナルで `git pull` して取り込む（このファイルは、消さないでください）。
5. **HTTPSを有効にする：** DNSが反映されるまで、数分〜最大24時間かかります。「Enforce HTTPS」にチェックが入れられるようになったら、チェックを入れる。
6. **QRコードを作り直す：** `python3 scripts/make_boards.py --base-url https://（独自ドメイン）` を実行する（掲示板のコードは変わらず、QRコードの中のURLだけが変わります。Supabaseへの登録のし直しは、不要です）。
7. **動作を確認する：** `https://（独自ドメイン）/rally/?stamp=（掲示板のコード）` が開き、スタンプが取れることを確認する。サイトのファイル自体には、公開URLを書いた箇所はありません（相対パスで書いているため）。`scripts/make_boards.py` の `DEFAULT_BASE`（初期値のURL）も、`--base-url` を付けない場合のために、新しいURLに書き換えておいてください。

- ドメインの更新を忘れると、サイトが開けなくなります。自動更新を有効にすることをおすすめします。

## 注意

同じ参加者IDで同じスタンプを再取得した場合も `scan_events` には履歴が残り、
`stamp_claims` には初回取得だけが保存されます。初回取得順はSupabase側で確定します。
